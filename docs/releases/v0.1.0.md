# Dockey 0.1.0 — native alpha

Dockey is a native SwiftUI/AppKit Mac app for an existing local Docker Engine. This first alpha brings the approved grouped-list design to a working native application.

## Included

- Compose-label grouping, standalone containers, search, and state filters.
- Explicit start, stop, and restart actions for existing containers and groups, with pending state and per-container results.
- Bounded live logs, redacted inspection, mounts, ports, and resource metrics.
- Event-driven container updates and visible-only streaming metrics, with scoped in-memory caches.
- Read-only image, volume, and network browsing.
- App-local selection of a Unix-socket Docker context; the global Docker CLI context is unchanged.
- Light, dark, and system appearance, compact/comfortable density, log preferences, stop confirmation, and connection settings.
- Per-user install/uninstall scripts, ZIP archives, and matching SHA-256 files.
- Matte charcoal macOS Dock icon with a larger mascot and soft teal glow.
- Original service badges for ClickHouse, MongoDB, Redis, and PostgreSQL images.

## Install

Requires **macOS 14 or later** and an independently installed, working Docker CLI and local engine. Dockey does not bundle Docker, Colima, or a Linux VM.

Choose `arm64` for Apple Silicon or `x86_64` for Intel. Download the ZIP and its matching `.sha256` file into the same folder, verify with `shasum -a 256 -c FILE.zip.sha256`, then extract and move `Dockey.app` to your Applications folder.

**These alpha artifacts are ad-hoc signed. They are not Developer ID signed or notarized.** macOS may block a quarantined downloaded build. Building locally from reviewed source is also supported. See the [installation guide](https://github.com/cxkw-dev/dockey-ui/blob/main/docs/install.md) for tool requirements, Gatekeeper guidance, updates, and exact-path removal.

## Scope and limitations

Group actions control existing containers; they do not apply Compose files, create missing services, or promise Compose dependency ordering. Container creation, deletion/prune, terminal sessions, remote endpoints, VM configuration, and automatic updating are outside this alpha. Quitting or uninstalling Dockey leaves the engine and its resources in place.

The project has not established compatibility with every engine/runtime version or every supported macOS release. CI builds both architectures and gates publishing on the Swift tests, disposable installation/archive checks, and a bounded native launch check of the copied app's resources and demo screenshot. Native screenshots use the isolated synthetic demo mode. Live Docker smoke testing is a separate, explicitly scoped check; fixtures and CI alone are not live-engine proof.

Feedback and reproducible bug reports are welcome in [Issues](https://github.com/cxkw-dev/dockey-ui/issues). Remove private resource names, paths, credentials, and log content from reports. Report vulnerabilities through the private channel described in [SECURITY.md](https://github.com/cxkw-dev/dockey-ui/blob/main/SECURITY.md).
